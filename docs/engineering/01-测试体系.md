# 测试体系

> 30 个测试文件，283 个用例，覆盖全部模块。核心设计理念：**环境完全隔离，所有测试数据落在临时目录，绝不污染真实数据。**

---

## 四层架构

```
          ┌──────────────────────────────┐
          │  第四层：CI 触发层              │  GitHub Actions
          │  何时测、怎么阻断                │  push/PR → pytest + lint
          ├──────────────────────────────┤
          │  第三层：测试层                 │  30 测试文件
          │  API 测试 + 逻辑测试 + 集成测试   │  283 用例
          ├──────────────────────────────┤
          │  第二层：辅助层                 │  conftest fixtures
          │  client · auth_token · mock_llm │
          ├──────────────────────────────┤
          │  第一层：隔离层                 │  conftest 环境变量 + 路径 + 清理
          │  临时目录 · 禁用限流 · 自动清理   │
          └──────────────────────────────┘
```

## 第一层：隔离层

### 执行顺序不可颠倒

Python import 机制决定了：如果先 `import app.config`，settings 对象已经创建好、路径已经指向真实目录了，再改环境变量就晚了。所以 conftest.py 的代码分三段：

**第一段（在 import 任何 app 模块之前）**：

```python
TEST_ROOT = tempfile.mkdtemp(prefix="orbit_test_")
os.environ["DATABASE_URL"] = "sqlite:///" + os.path.join(TEST_ROOT, "tenant.db")
os.environ.pop("LLM_API_KEY", None)    # 强制无 key，所有 LLM 调用走 mock
os.environ["PYTEST_RUNNING"] = "1"     # 跳过生产级配置校验
```

**第二段（import 之后，patch 路径）**：

```python
settings.rag.storage.persist_dir = os.path.join(TEST_ROOT, "chroma_db")
settings.UPLOAD_DIR = os.path.join(TEST_ROOT, "uploads")
memory_db.DB_PATH = os.path.join(TEST_ROOT, "memory.db")
```

**第三段（autouse fixture，每个测试后自动清理）**：

```python
@pytest.fixture(autouse=True)
def _clean_state():
    yield  # 先执行测试...
    cache_clear()                        # 1. 清空语义缓存
    client.delete_collection(...)        # 2. 删除 ChromaDB 所有 collection
    _invalidate_count_cache()            # 3. 清除搜索计数缓存
    conn.execute("DELETE FROM global_switches WHERE key LIKE 'branch-lock:%'")
                                         # 4. 清理 Agent Loop 分支锁
```

第 4 条是关键——Agent Loop 多个测试共用 `project_dir=""`，分支锁 key 相同。上一个测试拿到锁没释放，下一个测试的 loop 会被 skip（false positive）。

## 第二层：辅助层（Fixtures）

### client fixture（session 级）

- 触发 FastAPI lifespan → 初始化 DB + 预热 embedding 模型
- 主动禁用 slowapi 限流（`auth_api.limiter.enabled = False`）
- `scope="session"` 整个测试会话只初始化一次

### auth_token fixture（function 级）

不走 API 层，直接调底层函数绕过限流：

```python
username = "pytest_" + uuid.uuid4().hex[:8]
result = register_user(username, "pytest_pass_123")
return create_access_token(username, result["user_id"])
```

用户名每次不同（UUID），避免重名冲突。

### mock_llm fixture（function 级）

不是简单的 `unittest.mock.patch`，而是**拦截 HTTP 并验证请求内容**：

```python
def fake_urlopen(req, timeout=None, **kwargs):
    # 记录请求细节
    recorder["requests"].append({
        "url": req.full_url,
        "headers": dict(req.header_items()),
        "body": json.loads(req.data.decode())
    })

    if body.get("stream"):
        # SSE 流式：构造 data: {...}\ndata: [DONE] 序列
        lines = [("data: " + json.dumps(chunk)).encode() for tok in tokens]
        lines.append(b"data: [DONE]")
        return FakeResp(None, lines=lines)

    return FakeResp({"choices": [{"message": {"content": "Mock 回答"}}]})
```

测试可以验证"请求发到了哪个 URL、带了什么 Authorization、model 名对不对、temperature 对不对"——而不仅是"调用成功"。

## 第四层：CI 触发层

CI 不属于测试体系，而是测试体系的**执行者和门卫**。

```yaml
# .github/workflows/ci.yml
on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  backend-tests:
    strategy:
      matrix:
        python-version: ["3.10", "3.11", "3.12"]  # 三版本矩阵
    steps:
      - run: pip install -r requirements.txt
      - run: ruff check app/
      - run: python -m pytest test/ -v --tb=short
```

**关系总结**：测试体系回答"怎么测"，CI 回答"什么时候测、测完怎么阻断"。
