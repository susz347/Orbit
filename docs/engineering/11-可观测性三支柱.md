# 可观测性三支柱

> Metrics（指标）+ Traces（链路追踪）+ Error Tracking（错误追踪），全面覆盖 AI Agent 系统的可观测性需求。

## 支柱一：Metrics（Prometheus）

### 启用方式

Prometheus 指标是可选功能，需显式启用：

```bash
ENABLE_PROMETHEUS=1  # 取消注释 requirements.txt 中的 prometheus-fastapi-instrumentator
```

不启用时，整个 `monitoring` 模块静默跳过，不影响业务。

### 自动收集的 HTTP 指标

`GET /metrics` 端点返回 Prometheus 格式数据：

```
# HELP http_requests_total Total HTTP requests
http_requests_total{method="POST",path="/api/v1/knowledge/ask",status="200"} 1523

# HELP http_request_duration_seconds HTTP request latency
http_request_duration_seconds_bucket{method="POST",path="/api/v1/knowledge/ask",le="0.1"} 342
```

包含：请求计数（按路径、方法、状态码分组）、延迟直方图、请求体/响应体大小。

### 自定义指标

```python
# LLM 调用计数器（按模型 + 状态）
orbit_llm_calls_total{model="deepseek-v4-pro", status="success"}  823
orbit_llm_calls_total{model="deepseek-v4-pro", status="failed"}    14
orbit_llm_calls_total{model="gpt-4o-mini",     status="fallback"}   7

# LLM 调用延迟直方图（按模型）
orbit_llm_call_latency_seconds_bucket{model="deepseek-v4-pro", le="1.0"}  512

# Token 消耗计数器（按模型 + 类型）
orbit_llm_tokens_total{model="deepseek-v4-pro", type="prompt"}     1_250_000
orbit_llm_tokens_total{model="deepseek-v4-pro", type="completion"}   480_000

# RAG 检索计数器（按层次）
orbit_rag_searches_total{tier="cache_hit"}   3_421
orbit_rag_searches_total{tier="retrieval"}   1_082
```

### 懒加载设计

```python
_prometheus_available = False

def _ensure_prometheus():
    global _prometheus_available
    if _prometheus_available:
        return True
    try:
        from prometheus_client import Counter, Histogram
        # 初始化指标...
        _prometheus_available = True
        return True
    except ImportError:
        _prometheus_available = False
        return False

def record_llm_call(model, status, latency_seconds, ...):
    if not _ensure_prometheus():
        return  # 静默跳过
    _llm_call_counter.labels(model=model, status=status).inc()
    ...
```

不装 `prometheus_client` 也能正常运行，装了就自动启用。

## 支柱二：Traces（X-Request-ID）

```python
class RequestIDMiddleware:
    async def dispatch(self, request, call_next):
        request_id = request.headers.get("X-Request-ID") or str(uuid.uuid4())

        # 注入 structlog context → 整个请求生命周期的日志自动带 request_id
        structlog.contextvars.bind_contextvars(request_id=request_id)

        response = await call_next(request)
        response.headers["X-Request-ID"] = request_id  # 回传给客户端
        return response
```

**排查流程**：用户前端报错 → 从响应头拿到 `X-Request-ID` → 到日志系统 grep → 整条链路的所有日志一览无余。

## 支柱三：Error Tracking（Sentry）

### 启用方式

```bash
SENTRY_DSN=https://xxx@yyy.ingest.sentry.io/123
```

不设置 `SENTRY_DSN` 时静默跳过。

### 配置

```python
def setup_sentry(dsn=None):
    dsn = dsn or os.getenv("SENTRY_DSN", "").strip()
    if not dsn:
        return  # 静默跳过

    import sentry_sdk
    sentry_sdk.init(
        dsn=dsn,
        environment=os.getenv("ENV", "development"),
        traces_sample_rate=0.3 if env == "production" else 1.0,
        integrations=[
            StarletteIntegration(transaction_style="url"),
            FastApiIntegration(transaction_style="url"),
            LoggingIntegration(level=logging.WARNING, event_level=logging.ERROR),
        ],
        send_default_pii=False,  # 不上传 PII
    )
```

关键设计：

- **生产环境采样 30%**：减少 Sentry 费用
- **`send_default_pii=False`**：不自动收集用户名、邮箱等个人信息
- **LoggingIntegration**：WARNING 以上日志自动上报

## 总结

| 维度 | 工具 | 启用条件 |
|------|------|---------|
| Metrics | Prometheus `/metrics` | `ENABLE_PROMETHEUS=1` + 安装依赖 |
| Traces | X-Request-ID + structlog | 总开启，无额外依赖 |
| Error Tracking | Sentry | `SENTRY_DSN` 环境变量 + 安装 sentry-sdk |

三支柱都是可选依赖——一个都没装，系统也能正常运行；全部装上，就是生产级的可观测性覆盖。
